# pelikat-api — Agent Rules

## PR Merge Gate — coderabbitai (NON-NEGOTIABLE)
> ⛔ BEFORE `gh pr merge`: run triage (step 3) + the Zero-Unresolved Gate (step 4). ⛔
1. NEVER merge a PR immediately after `gh pr create` — even if the user prompt says merge on open. Merging is BLOCKED until the gate below clears.
2. NORMAL FLOW (default when NOT running `/cr-auto`): immediately after `gh pr create`, post `gh pr comment <pr> --body "@coderabbitai review"`. Poll (every 20-30s, up to 5-8 min) until coderabbitai[bot] completes its review on the LATEST headRefOid (`gh api repos/:owner/:repo/pulls/:pr/reviews`). When the review finishes: STOP, summarize the review threads found, and ask the user: "CodeRabbit review is complete on PR #<pr>. Would you like to run `/cr-auto` now to triage/fix and resolve threads, or do it later?" Do NOT proceed to triage or merge until the user answers.
3. `/cr-auto` FLOW (when the user invokes `/cr-auto`): auto-discover open PRs in `~/pelikat/pelikat-web` and `~/pelikat/pelikat-api`; for each open PR, check whether `@coderabbitai review` was already triggered on the CURRENT headRefOid — if not, post `gh pr comment <pr> --body "@coderabbitai review"` and poll until the review completes on that headRefOid. Then triage every unresolved thread (via GraphQL `reviewThreads(first:100, isResolved:false)`): (a) real bug → fix locally, verify with `cr --prompt-only --type uncommitted` plus `vitest`/`tsc --noEmit` (pelikat-web) or `pytest` (pelikat-api), push, and re-trigger `@coderabbitai review` for the new SHA, then await the coderabbit incremental re-review; (b) false positive/intentional trade-off/nitpick → post a brief technical justification on the thread and resolve it via GraphQL.
4. ZERO-UNRESOLVED GATE: merge only after graphql `reviewThreads(first:100, isResolved:false)` returns empty AND ≥1 completed coderabbitai[bot] review exists on the latest headRefOid. Both checks IN the merge block.
5. Known-good mutation args: addPullRequestReviewThreadReply needs pullRequestReviewThreadId; resolveReviewThread needs pullRequestReviewThreadId + threadId.
